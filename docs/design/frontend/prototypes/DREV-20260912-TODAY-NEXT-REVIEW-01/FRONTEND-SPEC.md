## 一句话方向

沿用暖白纸面、松绿状态和衬线分区标题，以“今天先做什么、下一次何时做什么”的两层层级替代大块空态；
未来安排保持只读，动作只在真正到期时出现。

## 问题

当前“待复习”只呈现 `due_date <= today` 的内容。当天刚确认的学习通常在明天首次复习，因此页面会同时
出现“待复习 0 项”和“今天记录的学习 1 条”。展开后又显示“确认一条学习记录后，复习日期会自动排到这里”，
虽然计划已经存在，却完全看不到日期或内容，容易被理解为没有生成复习计划。

现有 Todo 知识名称还被限制为单行省略号，较长的中文内容无法完整核对。

## 推荐交互

### 1. 分区标题

- 标题从“待复习”改为“复习安排”，覆盖今天到期和最近已排期两种事实。
- 有今天任务：`今天 4 项 · 约 15 分钟`。
- 今天为 0 且有未来安排：`今天 0 项 · 明天 3 项`；超过一天使用 `9 月 15 日 3 项`。
- 今天为 0 且后端没有返回后续安排：`今天 0 项`，不猜测“没有计划”。
- 整行保持 88rpx 以上触控区，点击仍只负责展开/收起；折叠偏好按孩子保存。

### 2. 展开态

#### 今天有到期内容

- 继续优先显示现有可操作 TodoCard。
- 长知识名称完整换行，不再单行截断；“完成”和“其他反馈”仍固定在行尾。
- 当天列表之后只显示一行低强调预告：`下一次：9 月 15 日 · 3 项`，不抢占今日任务层级。
- 点击预告展开最近日期的只读安排。

#### 今天无到期内容、但有未来安排

- 删除大面积通用空态，改为紧凑状态行：`✓ 今天没有到期内容`。
- 状态行下直接展开最近一次安排：日期、总项数、准确总预计分钟、科目/复习方式和知识点全名。
- 未来知识点不显示“完成”“其他反馈”或“带练提示”，避免提前改变确定性计划。
- 有 `source_submission_id` 的知识点行可进入来源记录详情；没有来源的旧数据保持纯只读，不显示假箭头。

#### 今天和未来都没有安排

- 显示紧凑真实空态：`今天没有到期内容` + `暂时没有后续复习安排`。
- 不再显示“确认一条学习记录后……”；该文案无法区分“从未记录”和“已完成全部计划轮次”。

### 3. 数量与展开

- 最近日期的 `total_count` 和 `estimated_minutes` 是服务端对完整集合的精确聚合，不能从首屏样本推算。
- 首屏最多呈现 5 个未来知识点；若仍有内容，显示 `还有 N 项 · 展开`。
- 每次展开最多追加 20 项，使用稳定游标；已加载名称完整换行且不重复。
- 加载更多失败时保留已展示内容，在原入口显示 `加载失败 · 重试`，不清空成“无安排”。

## 状态矩阵

| 状态 | 标题摘要 | 展开内容 | 可操作性 |
|---|---|---|---|
| loading | 上次摘要或骨架 | 与分区几何一致的骨架 | disabled |
| 今天有到期 | 今天 N 项 · 约 M 分钟 | 今日 Todo；下一次仅低强调预告 | 今日项可反馈，未来项只读 |
| 今天 0、未来有安排 | 今天 0 项 · 明天/日期 N 项 | 今日完成状态行 + 最近日期完整预览 | 来源记录可查看 |
| 今天 0、未来无安排 | 今天 0 项 | 两行紧凑真实空态 | 无 |
| 未来续页失败 | 精确总数不变 | 保留已加载项 + 原位重试 | 可重试 |
| 旧后端缺字段 | 今天 N 项 · 约 M 分钟 | 今日内容；不展示未来区 | 保持兼容，不伪造数据 |
| viewer | 与可写成员相同 | 同样可读 | 今天/未来均无反馈写入口 |

## 内容与无障碍

- 使用“到期”“已排期”“下一次”描述计划，不使用“掌握”“欠账”或能力判断。
- `今天没有到期内容` 同时使用勾图标和文字，不只依赖绿色。
- “还有 N 项 · 展开”“加载失败 · 重试”和来源记录行均有明确 aria-label，触控区不小于 44px。
- 日期以 `dashboard.day` 的 Asia/Shanghai 自然日为锚点；明天显示“明天”，其余显示“9 月 15 日”。
- 320×568 时标题摘要允许换为上下两行，不缩小字号；知识名称完整换行，操作仍在可视范围。
- 不新增动画；只沿用现有 120–220ms disclosure 过渡和 reduced-motion 行为。

## 视口与状态证据要求

实现前批准本 revision；实现后保留：

- 320×568：今天 0 + 明天多项 + 长中文知识名 + 展开入口；
- 390×844：本批准候选状态；
- 430×932：今天有 Todo + 下一次低强调预告；
- loading、无未来安排、续页失败、viewer、旧后端缺字段；
- 代表性 iOS/Android 微信开发者工具或真机证据作为发布门禁。

## 不采用的方案

| 方案 | 不采用原因 |
|---|---|
| 把明天内容直接算作“待复习” | 混淆到期事实，允许提前反馈会改变确定性计划 |
| 恢复未来 7 天负荷图 | 信息过重，违背今日页“一屏一决定”，且已在 MVP 决策中删除 |
| 只把空态文案改成“明天再看” | 仍看不到日期和知识点，不能证明计划已生成 |
| 客户端按 1/3/7 天自行推导 | 复制服务端业务策略，历史补录与反馈调整时会显示错误日期 |
| 一次返回所有未来复习 | 违反有界读取与响应预算，家庭长期使用后不可控 |
