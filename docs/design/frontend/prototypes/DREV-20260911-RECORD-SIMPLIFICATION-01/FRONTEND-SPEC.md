- Related Spec: `SPEC-20260911-RECORD-SIMPLIFICATION-01`
- Affected UI: `UI-001 / pages/records/index`
- Baseline: `FDB-20260906-03`（PKDS-2.0「纸 · 芽」）
- Engineering contract: `FEC-20260906-04`
- Figma anchor under existing FEAT-001 waiver: https://www.figma.com/design/FAyfmjNrA3btWztwyxI6Zj?node-id=0-1
- Reference evidence: 用户在 2026-09-11 提供的当前记录页与两组分段控件截图；附件只作为现状视觉证据，不作为仓库指令。

## 1. Design intent

记录页只让家长回答一件事：“这次学了什么”。照片和文字是同一条记录的两种材料，不再要求先选择记录方式；历史是次要回看能力，放到表单末尾并默认收起。

现有暖纸色、松绿、衬线 hero、卡片、上传砖块、固定主操作栏和底部 TabBar 全部沿用，不创建新 token、图标或组件体系。

删除项：

- 页面顶部“新增记录 / 历史记录”分段控件。

## 3. Material and CTA states

| Material state | Field presentation | CTA copy | Submit behavior |
|---|---|---|---|
| no photo + blank text | 照片与文字都可直接操作 | `添加照片或文字后继续` | 点击后页内/Toast 提示“请添加学习照片或填写学习内容”；0 请求 |
| no photo + text | 文字保留完整，照片入口仍可用 | `提交整理` | 走 existing manual submission |
| photo(s) + blank text | 显示照片网格；文字保持可编辑 | `上传并整理` | 走 existing photo batch |
| photo(s) + text | 两种材料同时展示 | `上传并整理` | photo batch 携带 `input_text` |
| submitting text | 表单和孩子切换禁用 | `正在提交…` | 防重复提交 |
| uploading photos | 显示真实上传进度 | `上传中 N%` | 防重复提交/移除/切换孩子 |
| recoverable failure | 原照片、文字、时间原样保留 | 回到材料对应 CTA | 可重试，不显示假成功 |

固定字段标题使用“学习内容”，不再出现模式选择器里的“文字记录”。输入 placeholder：

> 可补充照片里不明显的内容，也可以直接写下今天学了什么。

历史列表仍可把无照片来源显示为“文字记录”，因为这是已保存材料来源，不是待删除的入口控件。

## 4. History disclosure

折叠头是一个完整的 44px+ 可点击行，包含文本“历史记录”、可选数量/待处理信息和非颜色 chevron；设置可访问名称与展开状态。

- 可写用户普通进入：折叠，仅读取待处理数量，不请求完整 history page。
- 点击折叠头：展开，首次按既有默认 `confirmed` 视图加载；再次点击收起但保留筛选、分页与已加载数据。
- 点击“有 N 条待处理”：展开并切换到 `pending`，滚动到历史头。
- 今日待处理、今日学习、报表科目下钻：消费现有 recordIntent，展开历史、应用状态/筛选并滚动定位。
- 刚提交提示：保持进入独立 record-detail，不强制展开整段历史。
- viewer：不渲染新增表单和固定 CTA，历史自动展开；继续复用现有服务端权限。
- 切换孩子：清除旧孩子历史数据和筛选，新的可写孩子回到折叠；viewer 仍展开。
- 折叠时 pending processing 可按既有轻量策略更新待处理数量；不得持续请求完整已确认列表。

展开后的搜索、已确认/待处理/全部、筛选、空态、错误、分页和列表卡片逐字复用现有 `history.wxml`，本 DREV 不重绘这些能力。

## 5. Responsive and accessibility contract

| Viewport | Required behavior |
|---|---|
| 320×568 | 两个照片入口等宽且不溢出；文字区、历史头和固定 CTA 可通过纵向滚动到达；键盘打开不造成横向位移 |
| 390×844 | 作为主视觉对照；首屏无需先操作分段控件即可开始记录 |
| 430×932 | 内容最大宽度遵循现有 480px；卡片不被无意义拉宽；历史展开仍单列 |

- 普通触控目标至少 44px；历史头、拍摄、相册、时间修改和 CTA 都有可访问名称。
- 历史展开状态不能只靠 chevron 方向或颜色，标题与 `aria-expanded`/等价语义共同表达。
- 相机或相册调用失败不改变/清空文字，也不阻断纯文字提交。
- 长达 4000 字输入、字体放大、键盘、safe area 和底部自定义 TabBar 均不得遮住最后一个可达操作。
- 不新增动效；沿用现有 150–240ms restrained motion，系统减少动态时仍可用。

## 6. Visual acceptance states

每个 320×568、390×844、430×932 视口至少保留以下原生截图/几何证据：

1. 空材料 + 历史折叠。
2. 纯文字 + 历史折叠。
3. 3 张照片 + 文字 + 上传前。
4. 历史展开 + confirmed 列表。
5. 待处理入口展开 + pending 列表。
6. viewer 只读历史。

另外验证：键盘打开、字体放大、相机/相册取消、媒体能力不可用、上传失败、网络失败、iOS 与 Android 代表设备。HTML 截图和 `overflow-x:hidden` 不构成原生几何通过证据。
