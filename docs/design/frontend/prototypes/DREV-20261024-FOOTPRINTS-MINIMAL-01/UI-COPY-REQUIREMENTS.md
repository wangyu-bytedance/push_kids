## 拟合并到 UI 设计要求的正文

**界面用内容、状态和操作表达产品，默认不需要解释。**

- 每段可见文案都须服务于当前任务：识别对象、作出选择、完成操作或从实际错误中恢复。删掉不影响这些任务的句子。
- 不把 AI 的思考、实现细节、后台处理流程、内部约束、开发/验收说明或为假想问题预先辩护的文字放进产品界面。
- 同一对象、身份、状态和动作只表达一次；上方已选孩子，不再加“某某的足迹”一类重复标题。低频设置和管理操作按需展开。
- 优先改清楚标签、控件、层级和反馈；不要用一段说明弥补不清楚的交互。不要把删下来的说明改成新帮助弹层、折叠长文或更多提示。
- 用户当下需要的授权范围、实际错误与恢复动作、删除/放弃的直接后果，在发生的操作处简短呈现。避免在日常浏览界面反复播放这些说明。
- AI 候选/未确认、真实未知值、只读、归档、草稿实际到期日等影响当前操作的状态，用短标签表达。精简不改变业务规则和权限。
- 空态只保留状态和可执行动作；成功反馈不重复叙述刚完成的步骤；没有事实支撑的统计、占位人物和演示内容不得混入真实业务数据。
- 文案删掉后同步收紧布局，移除空容器和无消费者样式；不靠隐藏溢出、缩小文字或触控目标制造“简洁”。

## 拟合并到工程约束的验收要求

每次 UI 变更必须做一次“删字检查”：逐项标明可见文本是对象/数据、动作、当前状态、必要授权/后果还是冗余说明。前四类也要检查重复；最后一类直接删除。评审发现新增长段解释时，先检查交互是否应该调整。

以当前页面和当前动作判断必要性，不以“可能有用户不懂”作为堆叠提示的理由。无需新增逐字镜像测试；用真实状态、操作路径和三视口渲染证明界面仍可完成任务。
