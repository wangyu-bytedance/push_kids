# 家庭写入授权与通知租约事务边界

- Revision: `ARCH-20261124-CORE-TRANSACTION-01`。
- Status: Approved。产品负责人 2026-11-24 回复「批准，执行」。验收见[修复 Spec](../../../specs/active/BUG-20261124-CORE-REVIEW-REMEDIATION.md)。

家庭锁是成员撤权、家庭冻结和已绑定请求写入的串行边界。身份初读只定位要锁定的家庭。事务取得家庭锁后，以当前读确认同一绑定和有效角色，才能创建写上下文。绑定改到另一家庭时拒绝当次写，避免陈旧请求切换租户。SQLite 用实际写事务提供等效的序列化，保留只读请求和本人通知设置的既有合同。权限拒绝不产生业务写入和成功审计。

通知发送将现有每轮上限与投递所有权解耦。每次只领取即将处理的一条，使用当前状态、attempt 和截止时间识别所有权。回收仅条件更新同一过期租约。发送继续遵循目标到投递行的锁顺序，逐条从数据库读取当前偏好、接收标识和授权额度，避免在跨事务的 Session 中复用旧授权对象。投递结果及成功扣额在同一事务提交。维持 MySQL 5.7 与当前 schema；代价是每轮多次短领取事务，避免预占整个队列。双连接测试覆盖撤权先提交、发送先提交、迟到持有者、积压及同一订阅的竞争扣额。

风险包括旧版本继续处理通知、长锁等待，以及外部请求成功而本地结果未提交。新旧执行器互斥需在发布前核验。使用有界 Provider 超时和现有重试策略，版本回退时评估是否会重新打开原竞态。外部系统未提供可沿用的事务提交保证，保留尽力投递语义，无历史自动重放。应用无需新依赖或迁移。
