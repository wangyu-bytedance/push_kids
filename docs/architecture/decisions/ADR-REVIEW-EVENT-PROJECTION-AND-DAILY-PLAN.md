# ADR-001：Review 事件投影与每日计划快照

- Status: `ACCEPTED`
- Date: 2026-09-13
- Decision owner: 产品负责人
- Approval evidence: `SPEC-UNIFIED-REVIEW-20260913-02`
- Affected feature: `FEAT-001`

## Context

上传内容可能是新知识、今天计划内复习，或计划外历史知识。完整历史不能放入一次 Prompt；如果每天把未选中的到期项批量改到明天，又会丢失真实到期事实并产生与积压量成正比的写放大。读取时仅聚合 ReviewFeedback 也无法稳定支持“距上次复习最久优先”的高频排序。

## Decision

1. `ReviewFeedback` 保存不可变的确认事件；`ReviewItem` 保存可重建的当前投影：最近复习日、复习次数、间隔、热度、遗忘次数、策略版本和状态版本。两者在同一事务更新。
2. 下一复习日由 `planning` 的纯确定性策略 `curve_heat_v1` 计算，模型不得写日期。一个自然日内重复确认可增加审计次数，但不会重复推进曲线。
3. 每个孩子每天首次读取时，按分钟预算幂等创建一个 `DailyReviewPlan`。候选资格为 `due_date <= today`，排序为 `due_date → 从未复习/last_reviewed_on → id`；当天完成后不补题。
4. 未进入计划的到期项保持原 `due_date`，次日重新参与选择，不执行积压批量延期。
5. 初始 Agent 上下文只含本次材料、孩子配置、今日已确认知识和今日完整计划。历史候选通过只读、租户范围由服务端注入的索引工具按需检索；工具循环和结果量均有硬上限。
6. 只有家长确认后才创建或更新正式知识与 Review 数据；Agent 输出始终是可编辑提案。

## Alternatives considered

- 固定每天 6 条：简单，但条目耗时不同，无法直接表达家庭的时间预算。
- 每日随机抽样：能变化内容，但同日结果不稳定，且无法保证最早到期和最久未复习者优先。
- 未选项统一延期到明天：查询简单，但制造 O(backlog) 写入并篡改原始到期事实。
- 全历史注入 Prompt：语义判断直接，但 token、延迟和隐私暴露随历史线性增长。
- 直接接入 FSRS：算法成熟，但当前上传确认没有可靠的四档回忆评分，输入条件不足。

## Consequences

- 高频读取只需命中有界索引和当日计划，Review 最近事实为 O(1) 投影读取。
- 每次确认会多写一条审计事件并更新一个投影；首次创建当日计划只写预算内的有限条目。
- 策略升级必须更换 `policy_revision`，保留旧事件，使投影能够重建和审计。
- 计划快照使当日集合稳定；代价是当天新到期或积压项不会自动补入，需要到次日重新计划。

## Verification

- 纯策略边界、同日幂等推进和延期行为单元测试。
- new / today_review / history_item 确认事务集成测试。
- 历史检索租户隔离、返回上限和 Agent 工具预算测试。
- Alembic 升降级、旧反馈回填及索引存在性测试。
- 大积压读路径查询数、结果上限和无批量改期测试。
