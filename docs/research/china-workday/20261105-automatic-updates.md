# 法定工作日数据的后续年份与自动获取

2026-11-05本轮只读核验；这是[文案任务Spec01](../../../specs/completed/FEAT-001-WORKDAY-COPY-CLEANUP.md)的Discovery，不是已配置的同步任务或运行时架构。

当前本地精确依赖`chinesecalendar==1.11.0`。上游[PyPI主页](https://pypi.org/project/chinesecalendar/)与[源码README](https://github.com/liriansu-opus/chinese-calendar)本次仍明确2004–2026，上游说明次年安排依赖国务院公告后更新，通常在11月前后。当前实现选择离线包且没有自动升级链；因此后续年份尚不能被可靠分类。通用历法可计算春节等日期，具体连休/补班仍以年度正式文件为准，不能由日期公式代替。

本次搜索[国务院政策库](https://sousuo.www.gov.cn/zcwjk/policyDocumentLibrary?q=%E8%8A%82%E5%81%87%E6%97%A5%E5%AE%89%E6%8E%92%E7%9A%84%E9%80%9A%E7%9F%A5&t=zhengcelibrary)及官方年度通知，没有检索到2027/2028正式全国安排。此为检索结果，不是对政府所有发布渠道的绝对不存在证明；后续同步须重新检查。2026正式通知为[国办发明电〔2025〕7号](https://www.gov.cn/zhengce/content/202511/content_7047090.htm)。

检索命中的[武汉市政府2026-11-01转载](https://www.wuhan.gov.cn/zwgk/tzgg/202611/t20261101_2871857.shtml)说明2027年春节与周末顺连的可能性及2028中秋国庆合并原则，未提供两个年度完整放假与补班日期；不能代替年度通知或完整覆盖来源。

## 已核验的自动化来源

[NateScarlet/holiday-cn](https://github.com/NateScarlet/holiday-cn)公开提供年份JSON、原始公告papers列表、每日是否休息与节日名。其[官方仓库CI配置](https://github.com/NateScarlet/holiday-cn/blob/master/.github/workflows/main.yml)实际为每日定时运行update脚本，支持数据变化后发布版本；可以借鉴或作为结构化候选源，仍须核对papers与数据完整性。

- [2027.json](https://raw.githubusercontent.com/NateScarlet/holiday-cn/master/2027.json)本次实际内容为`year=2027, papers=[], days=[]`：空占位，不是已覆盖2027。
- [2028.json](https://raw.githubusercontent.com/NateScarlet/holiday-cn/master/2028.json)本次返回404：不可当作普通全年周一至周五。
- 上游提示年度按公告标题归属，12月日期可能受下一年度文件影响，因此不能只拉目标年而漏相邻年文件；与周末连休的普通周末未必列入days，不能把列表当完整365天分类。

## 可执行的三条路线（均未实施）

| 路线 | 实际工作 | 对本仓库影响 |
|---|---|---|
| A. 自动检查/升级离线包 | 定时查PyPI新版本→下载候选→核对官方文件/完整覆盖→更新精确版本与uv.lock→全年/边界/提醒测试→生成待审变更→既有后端发布 | 最小变更；依赖上游维护时效，仍需后端发布，不自动漂移版本 |
| B. 同步结构化年度快照 | 定时拉holiday-cn指定版本JSON及papers→校验官方来源、非空/日期/冲突/相邻年→与已有全年结果比对→生成版本化本地资源→测试与待审变更→后端发布 | 不必等待Python包更新；需批准activities数据资源/加载合同，运行时保持离线 |
| C. 直接解析国务院公告 | 定时抓官方搜索/文件→解析标题年份、假期区间和补班日→结构化候选→独立复核/自动校验→同B固化/测试/发布 | 最靠近权威来源，但网页/文案变化会增加解析维护成本 |

建议先A，抓取结构化候选用B作监测/交叉核对；若上游包迟迟未更新且已存在正式公告，再单独批准B的数据合同。C可作候选源，解析不确定时不得把推测写成正式数据。不存在一次抓取即可确认无限未来年份的办法；2027/2028/后续年份共用同一同步流程，在各年正式安排可核验后自动纳入。

## 推荐同步流水线的边界

`定时发现新公告/新版本 → 有界下载候选 → 官方papers/年份/日期及跨年校验 → 全年与回归测试 → 版本化变更/待审PR → 既有发布门禁 → 后端采用新快照`

定时执行可部署在项目实际CI或现有云端调度器；本仓库当前没有`.github/workflows`，不假设已接入GitHub Actions。没有在本会话创建Codex定期提醒、外部任务、PR、Webhook、云调度或自动部署。

没有公告/空表/下载失败时保留最近已验证版本，下一次继续检查，缺覆盖是运维状态；产品编辑页不展示包版本、覆盖年份和长防御说明，实际受影响结果仅以短未知状态表达。只获取公开日历，无需孩子/家庭标识；发布仍遵循已有手册，不能把自动获取等同于自动生产发布。
